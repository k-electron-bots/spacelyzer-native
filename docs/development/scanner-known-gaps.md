# Scanner known gaps (engine, as of this note)

Verified on Linux with the portable enumerator only. None of this is verified on macOS, and the macOS bulk backend (`scan_macos.rs`) is not compiled in Linux CI.

- **Unreadable entries on macOS are still silently dropped.** The portable enumerator now records an entry whose metadata cannot be read (and an iterator failure) in the skipped list. The macOS `getattrlistbulk` enumerator never reports per-entry failures (`failed` is always 0), so on macOS such entries can still vanish from totals with no disclosure. Not fixed, not testable here.
- **Non-UTF-8 names are left out of the tree and listed as unreadable (lossy).** Their bytes are not in any total. A non-UTF-8 scan root is refused. This is a recall limit, not raw-path identity. macOS Unicode normalization (NFC/NFD) behavior is unaudited.
- **Skipped paths with U+FFFD are flagged lossy**, including a real name that contains that character.
- **Symlink targets are never read.** Ancestor symlinks above the canonicalized root, and swapped ancestors below it, are resolved by the OS at call time (see `inspect.rs`).
- **Separate volumes (`SeparateVolume`) are untested** (needs a second filesystem). The Swift footer "unreadable" count still includes user-excluded and separate-volume entries until Swift consumes the counts-by-reason ABI.
- **Volume capacity** (`spz_volume_info_status`) is raw statvfs: no purgeable space, snapshots or container sharing. It can block on a hung mount, so a consumer must call it off the UI thread.
- **Exclusions** are exact-path and apply to any entry kind. A requested exclusion with no observed entry is reported as "unobserved" with a reason (not seen, inside a skipped subtree, not matchable). This is not proof the path is absent: a request under an excluded, unreadable or separate-volume subtree was never visited. Excluding one hard link keeps the inode counted through another scanned link. Matching is plain string equality, so case-insensitive or Unicode-normalized spellings on macOS are untested. A scan rooted at "/" with an exclusion directly under it is not tested.
- **First hosted-macOS run (compile-check, Actions run 37209485237, commit ea799bae, macOS 26.6.2, Xcode 26.6).** Dependency allowlist passed. Rust lib tests 15/15 passed. The `dupes` test binary ran 19 passed, 1 failed: a test fixture tried to create a non-UTF-8 file name and APFS refused it (errno 92, EILSEQ). That was a fixture assumption, not an engine result, and the affected tests now report SKIPPED off Linux. Cargo stopped at that failing binary, so the other integration test binaries and the whole failpoints run did NOT execute on macOS: no macOS result exists for them. The universal engine build succeeded, and the Swift universal release build succeeded with 0 errors and 20 warnings (10 unique). No runtime or UI evidence.
- Test fixtures that may behave differently on macOS and were never reached there: `scan_oracle` compares the default backend (getattrlistbulk on macOS) against `lstat` blocks*512, which may legitimately differ on APFS; `volume_abi` used a GNU `stat -f -c` oracle (now gated to Linux).
